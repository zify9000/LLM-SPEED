## 加工方式（README 的记载）

1. 取上游文本 `*** START OF THE PROJECT GUTENBERG EBOOK ***` 与
   `*** END OF THE PROJECT GUTENBERG EBOOK ***` 标记之间的正文，依次
   去除 PG 英文页眉/页脚与残留英文行、U+FFFD 字符；
2. 移除句内空白（源文本硬换行）；
3. 按句切分后聚合成 **150~260 字符**的块（块边界落在句末），**仅保留中文占比
   ≥ 0.8 的块、丢弃 < 40 字符的碎块**；
4. 块间以 `---` 分隔（本文件 618 处）。
   **不做**字词改写、繁简转换或标点替换。

## ⚠ 内容确有缺失，成因待确认（不猜）

**决定性检查**：取上游每个回目标题之后的 80 字符正文，检查是否出现在本仓语料中——
**111 回里有 16 回的开篇正文缺失**，例如第一回（`此開卷第一回也．作者自云：…` 整段
不在本仓，本仓该文件直接从 `自又云：…` 开始）、第六/十/十一/十二/十五/十七/十八回等。

这个缺失量**不能仅用 README 记载的过滤规则解释**（"中文占比 <0.8 的块""<40 字符的
碎块"都解释不了纯中文开篇段落的整段消失）。因此以下两种可能必须由语料作者确认：

- **(A) 同一份 PG 文本 + 更激进的裁剪**：某些段落被过滤/手工删掉了。若如此，
  请说明裁剪规则并从 README 补记（现有 README 的规则不完整）。
- **(B) 换用了另一版本/另一次校勘**：《紅樓夢》程甲本／程乙本／脂評本文字与篇幅
  互不相同。若如此，必须在上面"来源"表里写明**实际版本**，并注明"与 2026-08-14
  之前的存档语料不可比"。

**在确认之前本文件不写死结论**——`数据宁可缺不可假`。核对方法：挑上表任一缺失回
（如第一回），在本仓语料里搜该回后半段的任意句子——若在，说明是"删了开头若干段"；
若整回都搜不到，说明是版本差异。

## 与测量口径的关系

- 创意场景按句切块、块级乱序拼成确定性长流（ADR-0005/0065）；**83 万字符**
  的体量把"内置池循环点"推到 512K 档之后——这是选这份语料的原因（内置回退池
  仅 672 字符，4K 档就循环 ~9 遍，会注水 decode）。
- 正文为真实文学作品，文件结构/句式复用让 MTP 按真实口径生效，而不是照抄
  单段循环文本造成的投机采样虚高。
